# 0.4.0 全项目重构与验证（2026-11-15）

本次交付包含源码重构、已复现缺陷修复、回归测试、文档及本地运行程序更新。本文记录该版本的重构范围、验证结果和已知限制。

## 改动与证据

| 问题 | 根因 | 0.4.0 行为 | 验证 |
| --- | --- | --- | --- |
| 子 agent 请求 `input[N].content` 缺失 | 官方适配器把非 message 项统一删 content，包含 agent_message | 仅处理已知推理/工具类型；agent 和未知项原样保留 | 真实故障历史只读检查、8 路回环 HTTP 并发、官方在线请求 |
| Max/Ultra 被压成 xhigh | 目录适配沿用旧客户端 effort 枚举 | 保留账号档位和未来非空 effort，仅去重 | 单元测试、0.167 的 model/list、当前账号目录 |
| 启停后恢复历史失败 | SQLite provider 被迁移，JSONL 身份不变；新客户端校验默认 provider | 完全移除 SQLite 写入；原生/网关身份稳定，只切换连接地址 | 两类身份各两轮启停、真实 thread/resume、SQL 索引保持不变的 CLI 回归 |
| 停止/卸载后不能重新安装 | 保留的直连别名仍被当成“已接管但丢备份” | 区分直连别名与网关接管 | 卸载、重新配置、再次启停回归 |
| Store 运行时漏检、旧运行时被选中 | WindowsApps 不能可靠枚举；同步后的旧文件有更新 mtime | 从当前用户包注册信息发现 Store 路径，按程序报告版本选择 | 本机从 0.167.0-alpha.3.2 改为选择 0.167.0-alpha.4.1；版本排序回归 |
| 修改协议容易影响服务控制/传输 | 代理大文件同时承担多种职责 | 协议、路由、HTTP 策略、上游传输分别维护；应用、设置、模型、系统模块分组 | 迁移前后功能回归、Clippy、架构文档 |

生产依赖不再包含 rusqlite；仅测试夹具使用它验证网关不修改索引。程序没有数据库写入路径。

## 实测结果

- 73 项 Rust 单元/组件测试通过；覆盖协议、头隔离、SSE 增量与断开释放并发、错误透传、配置恢复、锁和进程身份。最后运行时发现修正另行执行其 2 项定向回归，通过。
- 18 项真实 Windows CLI 进程测试通过：启停/重启/卸载/重装、端口冲突、过期及复用 PID、第三方配置、隔离数据目录等。
- Windows PowerShell 5.1 控制台回归通过；UAC 为模拟，不发生真实提权或业务操作。
- `cargo fmt --all -- --check`、`cargo clippy --offline --locked --all-targets -- -D warnings` 通过。同步盘部分增量缓存无法硬链接时由 Rust 改为复制，不影响构建；无源代码 Clippy 告警。
- Release 构建通过，安装入口为项目根目录 `codex-gateway.exe`，本地服务健康检查返回 0.4.0。
- 当前 Store 客户端 0.167.0-alpha.4.1：原生 openai 与旧 codex_gateway 各两轮启动/停止，模型目录和相同身份的历史恢复均通过。不同身份被拒绝的限制也被显式测试；使用匹配身份启动的独立 app-server 可恢复另一种历史。
- 旧主会话和子会话兼容性在本地离线验证通过，原历史文件 SHA-256 检查不变；没有发送历史给上游。
- 官方在线烟雾测试：一次低档位 GPT-6 Luna 合成 agent_message 请求，HTTP 200，正文标记匹配，SSE completed。没有启动真实子 agent，没有执行模型工具。
- DeepSeek Flash、Pro 的文本和函数调用基础接口探测通过；这不是长任务能力评测。
- 模型目录保留账号公布的档位，不添加账号未公布的高级档位。

## 保留边界

1. 不同 provider 的旧会话仍受客户端身份检查约束。网关已停止制造索引/原始历史不一致，但不会自动修复旧版已经迁移过的所有索引。恢复方法见 [诊断文档](DIAGNOSTICS.md)。第三方 provider 切换同样受该客户端约束。
2. 已验证 agent 协议及并发传输、官方接受合成消息；没有验证桌面 UI 启动完整自主多 agent 长任务，也未对每种模型/每个档位做付费评测。
3. DeepSeek 不具备所有官方工具和服务端 compact 能力；停止网关后的官方直连也不执行跨模型历史过滤。远程托管会话不经过本地网关。
4. 账号登录失效、上游协议变化和未来客户端行为仍可能影响使用。0.4.0 的未知项透传能避免网关破坏新字段，不等于上游会接受任意扩展字段。
5. 本次没有更换全部依赖或执行完整依赖漏洞扫描。保留已锁定依赖；测试和工程分层用于降低回归风险，不构成“以后没有 bug”的保证。

## 维护入口

源代码责任边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。运行离线测试不需要真实凭证；在线烟雾测试必须显式提供 `--live`。

安装后完全退出并重新打开 Codex，以载入新模型菜单。仅重启网关即可应用协议修复；不必删除或重建原始会话。
